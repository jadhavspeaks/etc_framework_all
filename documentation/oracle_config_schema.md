# Oracle Table Schema Documentation

This document provides details for the Oracle tables used by the ETL Framework.

## Table: `JOB_CONFIG`

Central configuration table for all ETL jobs.

| Column Name                     | Data Type          | Nullable | Default Value      | Constraints/Checks        | Description                                                                                                | Example                                           |
|---------------------------------|--------------------|----------|--------------------|---------------------------|------------------------------------------------------------------------------------------------------------|---------------------------------------------------|
| `job_name`                      | `VARCHAR2(255)`    | NOT NULL |                    | PRIMARY KEY               | Unique human-readable name for the ETL job. Serves as Primary Key.                                         | `daily_sales_hdfs_to_hive`                        |
| `job_description`               | `VARCHAR2(1000)`   | YES      |                    |                           | Detailed description of the job''s purpose.                                                              | `Loads daily sales data from HDFS Parquet files into Hive summary table.` |
| `is_active`                     | `CHAR(1)`          | NOT NULL | `''Y''`              | CHECK (is_active IN (''Y'', ''N'')) | Flag to enable (Y) or disable (N) the job.                                                               | `Y`                                               |
| `source_type`                   | `VARCHAR2(50)`     | NOT NULL |                    |                           | Type of data source (e.g., FILE, KAFKA, JDBC, HIVE_TABLE).                                               | `FILE`                                            |
| `source_connection_details`     | `VARCHAR2(4000)`   | YES      |                    |                           | Connection string or details (e.g., JDBC URL, Kafka brokers, base file path, Hive db.table).             | `/mnt/landing/sales_data` (for FILE)              |
| `source_format`                 | `VARCHAR2(50)`     | YES      |                    |                           | Data format of the source (e.g., CSV, PARQUET, JSON, AVRO). Not used for HIVE_TABLE.                      | `PARQUET`                                         |
| `source_format_options`         | `VARCHAR2(1000)`   | YES      |                    |                           | JSON string for source-specific options (e.g., CSV delimiter/header, Kafka topic).                        | `{"header": "true", "delimiter": ","}` (for CSV)    |
| `source_schema`                 | `CLOB`             | YES      |                    |                           | Schema definition for source data (e.g., JSON schema, Avro schema string, DDL for temp view).              | `{"type":"struct","fields":[...]} `                 |
| `target_type`                   | `VARCHAR2(50)`     | NOT NULL |                    |                           | Type of data target (e.g., HDFS, ORACLE_TABLE, KAFKA_TOPIC, HIVE_TABLE).                                | `HIVE_TABLE`                                      |
| `target_connection_details`     | `VARCHAR2(4000)`   | YES      |                    |                           | Connection string or details for target.                                                                   | `sales_db.daily_summary` (for HIVE_TABLE)         |
| `target_format`                 | `VARCHAR2(50)`     | YES      |                    |                           | Data format for target (e.g., PARQUET, ORC). Often ignored for HIVE_TABLE.                               | `ORC`                                             |
| `target_format_options`         | `VARCHAR2(1000)`   | YES      |                    |                           | JSON string for target-specific options (e.g., compression codec).                                       | `{"compression": "SNAPPY"}`                       |
| `target_table_or_path`          | `VARCHAR2(1000)`   | NOT NULL |                    |                           | Name of the target table, HDFS directory, or Kafka topic.                                                | `sales_db.daily_summary_orc`                      |
| `load_type`                     | `VARCHAR2(50)`     | NOT NULL | `''INCREMENTAL''`    |                           | Type of data load (INCREMENTAL, FULL_RELOAD).                                                            | `INCREMENTAL`                                     |
| `target_write_mode`             | `VARCHAR2(50)`     | NOT NULL | `''overwrite''`      |                           | Spark DataFrame write mode (overwrite, append, ignore, errorifexists).                                   | `append`                                          |
| `transformation_mode`           | `VARCHAR2(50)`     | NOT NULL | `''AS_IS''`          |                           | Transformation mode (AS_IS, WITH_LOGIC, SCD2).                                                           | `WITH_LOGIC`                                      |
| `sql_logic`                     | `CLOB`             | YES      |                    |                           | SQL query used for transformations in WITH_LOGIC and SCD2 modes.                                         | `SELECT ... FROM {{source_view_alias}} WHERE ...` |
| `schema_mapping_logic`          | `CLOB`             | YES      |                    |                           | JSON defining column mappings (renames, type casts, defaults).                                           | `{"colA": "new_col_A", "colB": {"target_name":"new_B", "target_type":"int"}}` |
| `scd2_natural_keys`             | `VARCHAR2(1000)`   | YES      |                    |                           | Comma-separated list of columns forming the natural key for SCD Type 2.                                  | `product_id,store_id`                             |
| `scd2_change_tracking_column`   | `VARCHAR2(100)`    | YES      |                    |                           | Source column for detecting changes in SCD2 (e.g., last_modified_date).                                  | `last_mod_dt`                                     |
| `scd2_surrogate_key_column`     | `VARCHAR2(100)`    | YES      | `''sk_id''`            |                           | Name of the surrogate key column for SCD2.                                                               | `dim_pk`                                          |
| `scd2_valid_from_column`        | `VARCHAR2(100)`    | YES      | `''valid_from_ts''`    |                           | Name of the column for record validity start date/timestamp in SCD2.                                     | `eff_start_dt`                                    |
| `scd2_valid_to_column`          | `VARCHAR2(100)`    | YES      | `''valid_to_ts''`      |                           | Name of the column for record validity end date/timestamp in SCD2.                                       | `eff_end_dt`                                      |
| `scd2_version_column`           | `VARCHAR2(100)`    | YES      | `''version''`          |                           | Name of the column for record version number in SCD2.                                                    | `ver_num`                                         |
| `scd2_current_flag_column`      | `VARCHAR2(100)`    | YES      | `''is_current_flag''`  |                           | Name of the column indicating if SCD2 record is current (Y/N or true/false).                             | `current_ind`                                     |
| `partitioning_columns`          | `VARCHAR2(1000)`   | YES      |                    |                           | Comma-separated list of columns for target data partitioning.                                            | `load_date,region`                                |
| `job_priority`                  | `NUMBER`           | YES      | `0`                |                           | Priority for execution (lower number = higher priority).                                                 | `10`                                              |
| `max_retries`                   | `NUMBER`           | YES      | `3`                |                           | Maximum retry attempts on failure.                                                                       | `5`                                               |
| `retry_backoff_ms`              | `NUMBER`           | YES      | `60000`            |                           | Milliseconds to wait before retrying (can be used for exponential backoff).                              | `120000`                                          |
| `sla_threshold_minutes`         | `NUMBER`           | YES      |                    |                           | Service Level Agreement: max allowed job completion time in minutes.                                     | `60`                                              |
| `dependency_job_ids`            | `VARCHAR2(4000)`   | YES      |                    |                           | Comma-separated list of job_names this job depends on.                                                   | `previous_job_A,previous_job_B`                   |
| `audit_level`                   | `VARCHAR2(50)`     | NOT NULL | `''JOB''`            |                           | Auditing level (NONE, JOB for summary, RECORD for detailed - Hive based).                                | `JOB`                                             |
| `reconciliation_enabled`       | `CHAR(1)`          | NOT NULL | `''N''`              | CHECK (reconciliation_enabled IN (''Y'', ''N'')) | Flag to enable (Y) or disable (N) data reconciliation.                                                   | `Y`                                               |
| `reconciliation_config`        | `CLOB`             | YES      |                    |                           | JSON defining reconciliation parameters (type, columns, tolerance).                                      | `{"checks":[{"type":"record_count", "tolerance_percent":0.1}]}` |
| `dq_checks_enabled`             | `CHAR(1)`          | NOT NULL | `''N''`              | CHECK (dq_checks_enabled IN (''Y'', ''N''))     | Flag to enable (Y) or disable (N) Data Quality checks.                                                 | `Y`                                               |
| `dq_rules_config`               | `CLOB`             | YES      |                    |                           | JSON array defining Data Quality rules.                                                                  | `[{"rule_name":"col_A_not_null", ...}]`          |
| `notification_emails_success`   | `VARCHAR2(4000)`   | YES      |                    |                           | Comma-separated email list for success notifications.                                                    | `dev@example.com,ops@example.com`                 |
| `notification_emails_failure`   | `VARCHAR2(4000)`   | YES      |                    |                           | Comma-separated email list for failure notifications.                                                    | `dev@example.com,support@example.com`             |
| `notification_verbosity`        | `VARCHAR2(50)`     | YES      | `''BRIEF''`          | CHECK (notification_verbosity IN (''BRIEF'', ''DETAILED'')) | Verbosity of notifications.                                                                              | `DETAILED`                                        |
| `job_properties`                | `CLOB`             | YES      |                    |                           | JSON CLOB for storing additional, non-standard job properties or flags.                                  | `{"schema_drift_behavior":"include", "custom_param":"abc"}` |
| `log_masking_columns`           | `VARCHAR2(1000)`   | YES      |                    |                           | Comma-separated list of sensitive column names whose values should be masked in logs.                    | `ssn,credit_card_number`                          |
| `execution_authorization_flag`  | `CHAR(1)`          | NOT NULL | `''Y''`              | CHECK (execution_authorization_flag IN (''Y'', ''N'')) | If ''Y'', job needs explicit authorization to run (not auto-scheduled by dependency if orchestrator supports). | `N`                                               |
| `manual_trigger_only`           | `CHAR(1)`          | NOT NULL | `''N''`              | CHECK (manual_trigger_only IN (''Y'', ''N'')) | If ''Y'', job can only be triggered manually, not by automated schedulers/dependency chains.             | `N`                                               |
| `created_by`                    | `VARCHAR2(100)`    | NOT NULL | `USER`             |                           | User who created the job configuration row.                                                              | `API_USER`                                        |
| `created_ts`                    | `TIMESTAMP`        | NOT NULL | `CURRENT_TIMESTAMP`|                           | Timestamp when the job configuration row was created.                                                      | `2023-01-01 10:00:00`                             |
| `updated_by`                    | `VARCHAR2(100)`    | NOT NULL | `USER`             |                           | User who last updated the job configuration row.                                                           | `API_USER`                                        |
| `updated_ts`                    | `TIMESTAMP`        | NOT NULL | `CURRENT_TIMESTAMP`|                           | Timestamp when the job configuration row was last updated.                                                 | `2023-01-10 14:30:00`                             |
| `config_version`                | `NUMBER`           | NOT NULL | `1`                |                           | Version number for this job configuration, for optimistic locking or auditing changes.                   | `3`                                               |


## Table: `JOB_CONFIG_AUDIT_LOG`

Logs audit trails of CUD operations on `JOB_CONFIG` table performed via the API.

| Column Name                | Data Type        | Nullable | Default Value      | Constraints/Checks | Description                                                                               |
|----------------------------|------------------|----------|--------------------|--------------------|-------------------------------------------------------------------------------------------|
| `log_id`                   | `NUMBER`         | NOT NULL | Generated Identity | PRIMARY KEY        | Unique identifier for the audit log entry.                                                |
| `job_name`                 | `VARCHAR2(255)`  | NOT NULL |                    |                    | The `job_name` of the JobConfig entity that was created, updated, or deleted.             |
| `change_type`              | `VARCHAR2(50)`   | NOT NULL |                    |                    | Type of change: ''CREATE'', ''UPDATE'', or ''DELETE''.                                       |
| `changed_by_user`          | `VARCHAR2(100)`  | NOT NULL |                    |                    | User who performed the change.                                                            |
| `change_timestamp`         | `TIMESTAMP`      | NOT NULL | `CURRENT_TIMESTAMP`|                    | Timestamp of when the change was committed.                                               |
| `changed_fields_details`   | `CLOB`           | YES      |                    |                    | Optional JSON CLOB detailing specific fields changed, with old/new values for UPDATEs.    |
