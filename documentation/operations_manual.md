# Spark ETL Framework - Operations Manual

## 1. Introduction
This manual provides guidance for operators responsible for deploying, running, and monitoring ETL jobs within the Spark ETL Framework.

## 2. Deployment
- The Spark ETL application is packaged as a fat JAR file (e.g., `spark-etl-framework-1.0-SNAPSHOT-jar-with-dependencies.jar`) generated by the Maven build (`mvn clean package`).
- This JAR, along with the Oracle JDBC driver (if not already in Spark's classpath), needs to be available on the Spark cluster nodes where `spark-submit` will be executed.
- Ensure necessary configurations (e.g., `hive-site.xml` for Hive access) are present on the Spark classpath or provided to the Spark application.

## 3. Running ETL Jobs

### 3.1. `spark-submit` Command
Jobs are launched using the standard `spark-submit` script.

**Example:**
```bash
spark-submit \
    --class com.example.etl.MainApp \
    --master yarn \ # Or local[*], spark://host:port
    --deploy-mode cluster \ # Or client
    --name "ETL Job: [JOB_NAME_HERE]" \
    --conf spark.etl.oracle.url="jdbc:oracle:thin:@//your_oracle_host:1521/your_service_name" \
    --conf spark.etl.oracle.user="your_db_user" \
    --conf spark.etl.oracle.password="your_db_password" \
    --conf spark.etl.smtp.host="your_smtp_host" \
    --conf spark.etl.smtp.port="587" \
    --conf spark.etl.smtp.auth="true" \
    --conf spark.etl.smtp.starttls.enable="true" \
    --conf spark.etl.smtp.user="your_smtp_user" \
    --conf spark.etl.smtp.password="your_smtp_password" \
    --conf spark.etl.smtp.from="etl-framework@example.com" \
    --conf spark.etl.audit.basepath="/etl/framework/audit_logs" \ # Base HDFS path for file-based logs (if any) or for JobAuditor to derive Hive paths from if needed
    --conf spark.etl.param.processing_date="YYYY-MM-DD" \ # Example custom parameter
    --conf "spark.executor.extraJavaOptions=-Doracle.net.timezone_region=UTC" \ # Example for Oracle TZ issues
    --conf "spark.driver.extraJavaOptions=-Doracle.net.timezone_region=UTC" \
    /path/to/your/spark-etl-framework-VERSION-jar-with-dependencies.jar \
    [JOB_NAME_HERE]
```

### 3.2. `MainApp.scala` Command-Line Arguments
- **Primary Argument**: `job_name`
  - This is the unique name of the job configuration (as defined in the `job_name` column of the `JOB_CONFIG` Oracle table) that you want to execute.
  - It is **mandatory**.

### 3.3. Runtime Configurations (via `--conf`)
Many aspects of the framework and specific jobs are controlled by runtime Spark configurations. Key configurations include:

**Oracle Database Connection (for JobConfigLoader):**
- `spark.etl.oracle.url`: JDBC URL for the Oracle database housing `JOB_CONFIG`.
- `spark.etl.oracle.user`: Database username.
- `spark.etl.oracle.password`: Database password.
- `spark.etl.oracle.driver`: (Optional) Oracle JDBC driver class name (defaults to `oracle.jdbc.driver.OracleDriver`).

**SMTP Server (for NotificationService):**
- `spark.etl.smtp.host`: SMTP server hostname.
- `spark.etl.smtp.port`: SMTP server port (e.g., 587 for TLS, 465 for SSL, 25 for plain).
- `spark.etl.smtp.auth`: `true` or `false` if authentication is required.
- `spark.etl.smtp.starttls.enable`: `true` or `false` if STARTTLS is to be used.
- `spark.etl.smtp.user`: Username for SMTP authentication.
- `spark.etl.smtp.password`: Password for SMTP authentication.
- `spark.etl.smtp.from`: Email address to be used as the sender.
- `spark.etl.smtp.sendername`: (Optional) Display name for the sender.

**Auditing (Hive Table Names - if different from defaults):**
- The `JobAuditor.scala` uses hardcoded default table names like `etl_framework_audit.audit_summary`. If these need to be overridden without code changes, the framework would need to be enhanced to read these from Spark conf. (Currently not implemented, uses defaults).

**Custom Job Parameters (for SQL Logic substitution):**
- Any parameter prefixed with `spark.etl.param.` will be available for substitution in `sql_logic`.
- Example: `--conf spark.etl.param.processing_date=2023-10-26`. In SQL: `SELECT * FROM table WHERE date_col = '${processing_date}'`.

## 4. Monitoring Jobs

### 4.1. Spark UI
- Access the standard Spark Application Master UI (usually via YARN ResourceManager UI or Spark History Server) using the Spark Application ID.
- Monitor stages, tasks, performance, and view detailed logs (stdout/stderr) for executors and drivers.

### 4.2. Hive Audit Tables
- **`etl_framework_audit.audit_summary`**: Query this table for high-level job status (STARTED, SUCCESS, FAILED, SKIPPED_INACTIVE), record counts, durations, and short error messages.
  ```sql
  SELECT * FROM etl_framework_audit.audit_summary WHERE job_name_part = 'my_job_name' AND run_date = 'YYYY-MM-DD' ORDER BY run_datetime DESC;
  ```
- **`etl_framework_audit.job_run_details`**: Query for detailed run information, including the full `JobConfig` JSON used, Spark App ID, and full stack traces for failures.
  ```sql
  SELECT * FROM etl_framework_audit.job_run_details WHERE job_name_part = 'my_job_name' AND run_date = 'YYYY-MM-DD' ORDER BY run_datetime DESC;
  ```
- **`etl_framework_audit.rejection_events`**: Query for records rejected by Data Quality checks or other validation steps.
  ```sql
  SELECT * FROM etl_framework_audit.rejection_events WHERE job_name_part = 'my_job_name' AND rejection_date = 'YYYY-MM-DD' ORDER BY rejection_timestamp DESC;
  ```

### 4.3. Email Notifications
- Email notifications will be sent based on the job's outcome (SUCCESS, FAILED, SKIPPED_INACTIVE) to recipients defined in `JOB_CONFIG` (`notification_emails_success`, `notification_emails_failure`).

## 5. Troubleshooting Common Issues
- **Job Configuration Errors**: Check `JobConfigValidator` messages in `MainApp` logs or the `job_run_details` table if the job fails very early. Use the Web UI or direct Oracle queries to inspect and correct `JOB_CONFIG` entries.
- **SQL Errors in `sql_logic`**: Examine `SqlParserService` or `LogicalPlanValidator` errors in Spark logs or the `job_run_details` (full_stack_trace).
- **Data Quality Failures**: Check `DataQualityReport` details in logs or `job_run_details.dq_report_json`. Examine rejected records in `rejection_events` table.
- **Reconciliation Failures**: Check `ReconciliationReport` details in logs.
- **Classpath Issues**: Ensure Oracle JDBC driver and any other necessary JARs are correctly placed or included in `spark-submit`.
- **Hive Access Issues**: Verify `hive-site.xml` is on classpath and Spark user has permissions to read/write audit tables.

## 6. Using the Web UI (Brief Overview)
- The Web UI (accessible via its own deployment, typically on a web server) interacts with the Backend API (`etl-config-api`) to manage job configurations in the Oracle `JOB_CONFIG` table.
- **Features**:
  - List, view, create, edit, and delete job configurations.
  - Validate configurations before saving.
  - View audit trail of configuration changes.
  - Requires authentication (Basic Auth) and uses Role-Based Access Control (ADMIN, EDITOR, VIEWER).
